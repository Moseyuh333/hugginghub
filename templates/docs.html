How to use this server

This instance speaks the Hugging Face Hub HTTP API. Any tool built on huggingface_hub -- transformers, datasets, diffusers, the hf CLI -- works against it unchanged. The only thing you have to do is tell the library where this server is.

Pick a scope: per process, per shell, or per machine

There are three ways, and they differ only in how much gets redirected.

connect() is per process, not per file. It sets process-wide environment variables and patches huggingface_hub, so calling it once anywhere is enough for the whole program -- you do not need it in every file that imports huggingface_hub. It is also not machine-global: another Python process started separately still talks to huggingface.co unless you use the env var or the hook.

1. One Python program

Install the small shim once (it has no dependencies beyond huggingface_hub):

pip install ./python

Then at the top of your entry point:

import hugginghub hugginghub.connect("{{ base }}", token="hf_...") # from /settings/tokens from huggingface_hub import HfApi HfApi().whoami() # {"name": "you", ...}

Call it before import huggingface_hub for the cleanest setup. If huggingface_hub is already imported, connect() patches the loaded modules in place instead, so either order works.

What it changes: HF_ENDPOINT, HF_TOKEN if given, and HF_HUB_DISABLE_XET=1 (this server stores large files as Git LFS objects, not Xet). It also gives the instance its own download cache, ~/.cache/hugginghub/<host>, so a repo named like a public one never collides with it.

2. One shell session, no code change

Useful for scripts you can't edit, CI, or the hf CLI:

export HF_ENDPOINT={{ base }} export HF_TOKEN=hf_... export HF_HUB_DISABLE_XET=1 hf download admin/my-model --local-dir ./my-model

3. The whole machine

One command makes every Python process on the box use this server, with no imports anywhere. It writes a .pth file into site-packages and saves the endpoint to ~/.config/hugginghub/config.json.

hugginghub connect {{ base }} --token hf_... hugginghub install-hook hugginghub status # what is configured hugginghub uninstall-hook # undo it

Disable it for a single process with HUGGINGHUB_NO_AUTOHOOK=1.

Tokens

Reads on public repos need no token. Uploads, private repos and writes need one: create it under Settings → Access tokens (or hugginghub create-token <user> on the server). Use it as HF_TOKEN, as token= to connect(), or as the password in a git URL.

Upload and download

from huggingface_hub import HfApi, snapshot_download api = HfApi() api.create_repo("me/my-model", exist_ok=True) api.upload_folder(repo_id="me/my-model", folder_path="./my-model") snapshot_download("me/my-model", local_dir="./copy")

Files of 10 MB or more are stored as Git LFS objects automatically.

Loading a model

Because transformers goes through huggingface_hub, redirecting the hub is all it takes:

import hugginghub hugginghub.connect("{{ base }}", token="hf_...") from transformers import AutoTokenizer tok = AutoTokenizer.from_pretrained("admin/Qwen2.5-Demo-0.5B-Instruct")

Git

Every repo is a real git repository, so clone and push work directly:

git clone {{ base }}/admin/my-model cd my-model git lfs install # large files go through LFS git push

For a private repo, put the token in the URL: git clone https://user:hf_...@{{ base|replace('http://','')|replace('https://','') }}/admin/my-model. Push to refs/pr/N to open a pull request, exactly like the Hub.

What is implemented

Repos

create/delete/move, settings, repo_info, list_models/datasets/spaces, list_repo_tree, get_paths_info, list_repo_refs, list_repo_commits, branches, tags, super-squash

Files

resolve with Range requests, preupload, NDJSON commit, create_pr, hf_hub_download, snapshot_download, upload_file, upload_folder, LFS batch

Community

discussions, pull requests (refs/pr/N), comments, status changes, merge, likes, followers, user and org overviews

Git

clone, fetch, push over smart HTTP; git-lfs batch, upload, download; refs/pr/*

Not implemented, by design: inference endpoints, the Spaces runtime, jobs, papers, collections and billing. A Space here is a git repo with a card -- running the app is up to you.
